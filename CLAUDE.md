## What we're building

A daily news briefing read aloud, for Emil and a small group of friends (free, non-commercial). Each person creates a profile and picks topics (Google News sections or their own search words), preferred news outlets, the time and days they listen, a voice and a length. Each morning the app fetches their headlines, turns them into a short radio-style script, converts it to an MP3, and delivers it.

The site should look and feel like a modern SaaS product: landing page, sign-up flow, dashboard, settings.

A prototype already exists (single-file `morning-desk.html`, not in this repo yet). It reads Google News headlines with the browser's built-in voice, but only while the tab is open, and it has no AI summary.

Full architecture, diagrams and component costs: `docs/architecture.html`. Overview and build plan: `README.md`.

## Architecture

- **Build:** Emil + Claude Code → Git → GitHub (`emilgasparyan-droid/morning-desk`, private) → Vercel auto-deploys on push. Live: https://morning-desk-opal.vercel.app (Vercel team "Emil Team"; `morning-desk.vercel.app` belongs to someone else).
- **Daily run (Next.js on Vercel):** Vercel Cron (~5 AM) → `/api/generate`:
  1. Read each user's settings (Supabase)
  2. Fetch headlines (Google News RSS, fetched server-side, no CORS relays needed)
  3. Write the script (`lib/summarize.ts`)
  4. Text-to-speech → MP3 (`lib/speak.ts`; OpenAI, ElevenLabs or Google, not chosen yet)
  5. Save the MP3 (Vercel Blob)
- **Delivery:** web app player at each user's chosen time, private podcast feed (`/feed.xml`), optional email (Resend).

## Decisions and constraints

- **Audience: Emil + friends, free.** Vercel Hobby and the Google News feed only allow personal, non-commercial use. Going public or charging would need Vercel Pro and a licensed news API; flag this before building anything that assumes it.
- **Sign-in: email magic link via Supabase Auth.** No passwords, no Google sign-in for now.
- **Preferences live in Supabase** (`profiles` table, one row per user, `preferences` jsonb; schema in `supabase/migrations/`, run by hand in the SQL Editor). Row Level Security limits each user to their own row. During sign-up, choices are kept in localStorage until the email link is opened, then saved to the new profile (`lib/preferences.ts`).
- **Supabase project:** `hqdebundzpqbzsxuvlfo`. Its built-in email service only sends to the project team's own addresses and is heavily rate-limited, so friends can't sign in until custom SMTP (e.g. Resend) is set up.
- The browser uses only the publishable key. The secret key is for server-only jobs (the daily run) and must never reach the browser or Git. Never ask Emil for the database password.
- **No Claude API yet.** Emil wants to delay it. Until he says otherwise, `lib/summarize.ts` produces a plain headline read-out with no LLM call. Keep it behind one function so Claude API scripts are a one-file swap later.
- **Vercel Hobby (free, personal use only).** Cron runs once a day and can fire anywhere within its hour, so generate early and play later. Don't design anything that needs exact-minute server timing. One daily run makes every user's briefing; listening time only controls when it's shown.
- **Storage:** delete MP3s older than ~30 days in the daily run to stay under Blob's 1 GB.
- **Secrets** live only in `.env.local` (gitignored) and Vercel Environment Variables, never in code or commits. Never export `ANTHROPIC_API_KEY` in the shell: Claude Code would bill the API instead of Emil's Pro plan.
- **Env vars:** `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (set locally and in Vercel); later `SUPABASE_SECRET_KEY` (server only), TTS key (e.g. `OPENAI_API_KEY`), `CRON_SECRET`, `ANTHROPIC_API_KEY`. `NEXT_PUBLIC_` values are baked in at build time, so add them in Vercel before pushing code that needs them.
- `/api/generate` must reject requests that don't carry `CRON_SECRET`.
