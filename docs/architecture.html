Morning Desk Architecture
Voice AI project · System architecture

How Morning Desk is built and how it runs

Every piece of the daily news briefing app, from the editor where the code is written to the voice that reads your headlines each morning.

The system has two separate halves. It helps to keep them apart in your head, because the tools in one half never touch the other.

Half 1 · Build and ship

Happens when you change the app

You and Claude Code write code in Cursor or VS Code. Git records it, GitHub stores it online, and Vercel turns it into a live website.

Half 2 · The daily run

Happens every morning on its own

Vercel wakes the app up, it gathers headlines, Claude writes a script, a voice service records it, and you hear it at your time.

Half 1

From your editor to a live website

You describe what you want. Claude Code edits the files in your project folder. Each time you're happy with a change you commit it with Git and push it to GitHub. Vercel notices the push and publishes the new version within a minute or two.

Half 2

What happens every morning

No one has to have anything open. A scheduled job on Vercel calls one function in your app, and that function does five things in order. The finished MP3 is then handed to whichever way you like to listen.

One limit that shapes the design

On Vercel's free Hobby plan, a scheduled job can run only once a day, and Vercel may start it anywhere in that hour. A job set for 5:00 AM could run at 5:45.

That's why the app makes the briefing early and lets the delivery side handle exact timing. Your browser tab (the same trick as the prototype) or podcast app plays it at 7:30. If you later want a notification at the exact minute, the options are Vercel Pro, where jobs can run every minute, or a scheduling service such as Upstash QStash.

A typical morning

The same run, by the clock

  1. 5:00–5:59

    Vercel Cron calls /api/generate.

    Vercel
  2. + 2 sec

    The function loads your topics (Canada, Tech, Business) and pulls about 10 headlines for each.

    Supabase · Google News
  3. + 20 sec

    Claude picks the stories that matter, removes duplicates and writes a 4-minute script.

    Claude API
  4. + 40 sec

    The script becomes an MP3 in your chosen voice and is saved with today's date.

    Text-to-speech · Vercel Blob
  5. + 1 min

    The podcast feed now lists today's episode; your podcast app downloads it in the background.

    Podcast feed
  6. 7:30

    The open Morning Desk tab plays the briefing, or you press play in your podcast app.

Before you start

Accounts and keys

  • GitHub account, and Git installed on your computer
  • Vercel account, signed in with GitHub
  • Supabase project → SUPABASE_URL, SUPABASE_KEY
  • Claude Console API key → ANTHROPIC_API_KEY
  • Voice service key → e.g. OPENAI_API_KEY
  • A random password you make up → CRON_SECRET, so only Vercel's scheduler can trigger the briefing
Build order

How we'd put it together

Each step ends with something you can try, and each one goes live through the same commit → push → deploy loop.

  1. Set up the toolsInstall the editor, Git and Claude Code. Create the Next.js project and push it to GitHub.
  2. Deploy an empty appConnect the repo to Vercel so every push goes live. Confirms the whole pipeline works.
  3. Generate one briefingBuild steps 2–4 and trigger them by hand: headlines in, MP3 out.
  4. Save settingsAdd Supabase and the settings screen from the prototype.
  5. Automate itAdd the daily schedule, Blob storage and the podcast feed.
  6. PolishPick the voice, tune the script style, add email if you want it.
